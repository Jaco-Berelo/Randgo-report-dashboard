Notes on the data

  • Source: Berelo's monthly client redemption reports for April–September 2026. Covers 62 Randgo clients — every client with "Randgo" in its name plus Sanlam — including demo and test accounts.
  • Each month shows the codes issued in that month and the redemptions of those codes captured in that month's retailer feed. Codes issued in the last days of a month have little time to be redeemed before the feed closes, so utilisation is slightly understated.
  • April recalculated at code level: April's client reports counted every basket product line as a redemption (3 439 redemptions / R 62 462.00). Here April is counted once per redeemed code and value, the same way as May–September (3 556 redemptions / R 33 309.00).
  • June's client reports listed one row per code rather than one per basket product, so June's products issued and issuing value equal its code-level figures and are lower than other months. Sanlam's April report (shared separately) is laid out the same way: its 7 355 products issued come from that report's summary, and its issuing value is at code level.
  • May: the Pick n Pay, Dis-Chem and Baby City feed carried no transaction values, so those redemptions are counted but carry R0 value.
  • At Shoprite Checkers and Usave one basket code can be redeemed against several products, so redemptions can be higher than codes redeemed. At Pick n Pay, Dis-Chem and Baby City each redeemed code counts as one redemption.
  • Other clients benchmark: the average across all non-Randgo Berelo clients (Sanlam counted as Randgo), unnamed, from the same monthly client reports and calculated the same way. Available May–September only, as April reports were produced for Randgo clients only. Shown for utilisation rate and value utilisation only (percentages, so the comparison is not skewed by client size); the pill shows how Randgo compares over the same months.
  • Potential saving = face value of every unique code issued minus the value already redeemed (per client per month, never below zero).
  • Brands are read from product descriptions and are indicative. Stores are grouped by name. Client names are matched across months ignoring punctuation (e.g. "Clientele Royalty - CLI1RT04" and "Clientele Royalty CLI1RT04").
  • "Clientele Perks - Randgo - Checkers" (Apr–Jun) and "Randgo - Clientele Perks - CLI1_NS" (May–Sep) are the same programme and are shown together as Randgo - Clientele Perks - CLI1_NS. Both names issued codes in May and June, so those months combine the two.
